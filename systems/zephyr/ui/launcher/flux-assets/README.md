# FLUX Rev.04 reference

Native port of the user-supplied `aster-flux-v4-20261002-191041.zip`.
Coordinates, colors, ribbon transforms and gesture thresholds follow its
`FIRMWARE-PORTING.md`, `flux.css` and `flux.js`.

`../flux_icons.inc` contains 24×24 and native 40×40 A8 masks rasterized from the reference
package's Lucide SVG files (ISC license in `LICENSE`), plus an arrow and
an Aster asterisk drawn from simple line primitives. Application art is
read from each installed package's original ASTI `icon.bin`, never recolored
when it contains RGB565 data.

The firmware does not run the reference HTML/JavaScript or simulate its
sample application contents. It launches installed applications and uses
the device's existing services for Wi-Fi, storage, clock, brightness and audio.

`../flux_fonts.inc` contains native pixel-size A8 subsets generated by
`python tools/build_flux_fonts.py` from `resources/fonts/ui.ttf` using the
FreeType native-ppem hinting and full A8 coverage, without supersampling
or a 4bpp quantization round trip. Generate ui.ttf with
`tools/build_ui_ttf.py` first if needed. Font artwork retains the Droid /
DejaVu licenses in `resources/fonts/NOTICE`; the generator code is MIT.
These faces are specific to launcher chrome and do not change SDK font ABI.
Uncovered application names fall back to SD fonts.

Regenerate icon masks with `python tools/build_flux_icons.py` (CairoSVG and
Pillow). Licensed SVG sources are in `icons/`; 40 px ribbon icons use the
native raster instead of enlarging a 24 px mask.

Small launcher text uses at least 12 px for ASCII and 14 px for non-ASCII
labels. This intentionally increases the reference web design's 7–10 px
annotations for readability on the 320×480 physical panel. Native 12 px
coverage prevents the old scaled-SD fallback for the status-bar brand.
