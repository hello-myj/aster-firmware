# 连续音效实现与验收记录

2026-10-21，工作分支 `feature/continuous-audio`；基线为多指版本合并后的 main。作为 `sdk-v4.1.0-rc.1` 配套候选版本整理。依据工作区的《固件连续音效优化实施方案》实施。

## 已核对的实现映射

- 四槽 PCM、MP3 解码、动态音频线程与 I²S 输出：`platform/esp32s3/audio.c`。线程栈现有8192B，优先级6；APP线程优先级7。复用现有播放器，不新增每声部线程。
- 原有重采样：`audio_rate.h`。保留MP3原生输出采样率，不将音乐统一降为16kHz；旧get_info仍报告固定的原生PCM输入格式。
- Guest绑定/退出回收：`systems/zephyr/runtime/aster_native.c`、`aster_runtime.c`。新增结构必须复制校验后使用，不能留存Guest指针；退出/异常仍回收四槽。
- 公开契约源：`contract/include/aster/`；SDK通过现有导出/导入工具同步。新增接口采用加法ABI 4.1；4.0 APP继续兼容，新接口APP最低固件4.1，不能只靠运行时feature判断解决缺失导入。
- 模拟器：`src/peripherals.js`、`web/audio.js`；必须同时实现无声状态推进和浏览器声音行为。

## 初始问题与实施顺序

OutRun源码确认每19个逻辑步重播引擎片段。固件effect_load持effect_mu执行SD访问、现有音效会在BGM结束后随输出线程停下、audio_stop停止全部声部、WAV加载只接受固定44字节头。当前没有接入开发板，不能把源码分析当成I²S错误根因已确认。

先实现可由主机合成PCM验证的四声部DSP：循环/引入段、Q16变速、线性插值、平滑、交叉淡化、独立停止；接入现有混音锁和生命周期，移除持混音锁的SD读取。再补会话边界、诊断、CLI和SDK/模拟器。SD阻塞与解码/输出解耦、采样率切换及I²S实际水位需要独立验证，未通过前不得宣称低帧率与SD压力下连续性已验收。

## 接口及内存约束

首版新增play_ex、set_params、effect_stop，描述使用固定宽度size/version结构。已提供CLI相位/缓存/末块PCM峰值快照；完整公开诊断ABI尚未实现。四槽/每槽64KiB保持；旧play一次性重播与旧全局stop语义不变。BGM独立停止需明确新增控制入口，不能悄悄更改旧stop的作用范围。

DSP相位为64位Q16，每采样及时回绕；增益/变速平滑按输出采样推进。交叉区尾部与循环起点重叠，回绕跳到start+crossfade，稳态周期为end-start-crossfade个源帧。暂停不推进APP音效相位。混音先用32位累加，再饱和到PCM16。

目标额外内部RAM≤16KiB、PSRAM≤64KiB，不计已有PCM缓存，当前只是预算不是实测。现有TX slab为6×1536B、线程栈8KiB，不能重复计成新增分配；若后续分离SD/解码线程，必须另计栈和FIFO。未知的硬件欠载统计必须显式标为未知，不能用固定0作为验收证据。

## 内部优化第二轮：SD 预读与 PCM 环形缓冲（2026-10-22，待运行验证）

本轮继续在 `feature/continuous-audio` 修改，仅更新固件内部实现；ABI 仍为 4.1.0，SDK 导入、参数及模拟器行为均不变。上面的首版测试结果不能作为本轮修改的验收结果。

### 代码变化

- 新增 `platform/esp32s3/audio_file_reader.c/.h`：MP3 文件播放期间按需创建单个 SD 生产线程，优先级 7，使用 16 KiB PSRAM 环形缓存，每批最多读取 4096 B。空间不足一批时休眠等待消费者释放空间，避免按每个压缩帧发起零碎 SD 读操作。
- SD 读不持有输出锁、会话锁或预读队列锁；写入空闲区后再短锁发布有效字节。播放器只消费已发布数据，不等待 SD。已启动输出后遇到压缩数据不足时，沿用静音底轨混入音效的路径；这不是硬件欠载为零的证明。
- MP3 解码窗口改为批量整理，不再每消费一个压缩帧就搬移剩余窗口。解码后的 PCM FIFO 改为环形索引，移除每次提交 I²S 块后对剩余 PCM 的 `memmove`；EOF 补零与重置同步使用环形位置。
- 跳转前请求预读线程退出并 `join`，完成定位、MP3 同步及解码器复位后，按实际剩余文件长度重新启动预读。定位和同步失败不再被忽略。
- 结束、停止、初始化失败以及 EOF 后转纯音效会话，均先停止并等待生产线程，再关闭文件或释放缓存。暂停时生产者最多填满有界缓存后休眠，不持续读完整首歌。文件在预先确定的有效载荷长度之前返回零字节视为读取失败。
- 在线流仍使用原有 APP 写入环，不创建 SD 线程；原生 PCM/WAV 文件仍采用原有读取路径。

### 资源与边界

播放 MP3 文件时，新增动态 PSRAM 为 16384 B，内部 RAM 线程栈申请使用 `K_KERNEL_STACK_LEN(3072)`；另有线程对象、互斥锁、信号量及少量队列字段，当前微雪 ELF 的这些符号合计约 263 B（未计链接对齐和分配器开销）。PCM FIFO 沿用原容量，增加一个 4 B 环形头索引。闲置时不保留新增动态缓存和栈，少量静态控制对象保留。以上为代码/ELF 分项，不是运行峰值实测。

取消不会强制中止已经发给 SD 驱动的事务：需等待该次读取返回才能完成 `join`。若底层存储驱动永久阻塞，本层无法保证停止期限；禁止提前释放仍可能被读取线程访问的内存。既有全局 stop 的超时语义保留。

本轮完成的是“SD 读取与播放器解耦”。MP3 解码、混音和 I²S 提交仍由现有播放器完成；尚未实现独立输出消费者、无缝切歌、独立 BGM 停止或 OutRun 接入。不要把压缩预读队列当作 I²S DMA 队列或实时 DMA 水位。

### 已完成的实机检查

- 自生成 48 kHz 双声道、128 kbit/s、30.024 秒 MP3（480384 B），以及 44.1 kHz 单声道短 MP3（7105 B）。临时文件只写入独立测试目录，传输校验通过；测试后两文件与空目录均删除，未替换用户音乐。

- 首轮 20 次启停及交替暂停完成，但“全局内核堆每个字节均相同”的检查遇到 36 B 波动而中止后续步骤。补测 20 轮并每 5 轮取样，确认内核堆在 15276/15312 B 间短时变化后回落，未逐轮增长；第二轮端点均为 15276 B。libc 两轮端点均为 60060 B。不能将一次全局堆波动直接归因于音频泄漏，也不能据此宣称所有运行场景绝无泄漏。
