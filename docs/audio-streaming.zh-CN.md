# MP3 分段流输入与在线音乐（ABI 3.10）

2026-10-16 工作区增量，本地提交，未推送或发布。N1/N2既有接口保持兼容；这项工作新增音频输入能力，不代表MQTT等后续网络计划已实施。

## 实现边界

- 公共契约：`contract/include/aster/audio_stream.h`，open/write/finish/status/close五接口，feature18 `audio-stream`。正数会话句柄属于当前APP；数据先复制后返回，不保留WASM指针。退出、trap与初始化失败统一回收。
- 后端：32 KiB PSRAM输入环＋16 KiB连续解码窗口，复用minimp3和I²S输出；音质优化分支按MP3源采样率输出，详见[音质验证](audio-quality.zh-CN.md)。预缓冲约24 KiB或EOF后播放，欠载重新缓冲。按窗口跳过ID3，不整首复制或写SD。
- SDK示例：`apps/online-music`，申请公开128kbps MP3地址，固定2KiB待写块，保存部分写入尾部；成功HTTP EOF才finish，等待DONE，失败直接close。切歌先回收旧会话。
- SDK/开发手册同步ABI3.10；模拟器识别五个导入但不宣告此可选能力，返回ENODEV，没有用整文件播放冒充流播放。

## 网络配置与资源

日常HTTPS配置补齐16KiB TLS记录缓冲；旧日常配置继承1500字节，而N2诊断配置已经是16384，导致两者不一致。修正后微雪直连海外站点TLS握手成功。但海外源实测供给不足以播放320kbps，最终改用国内网络源。

两板TCP接收窗口由2KiB调为8KiB，RX packet 8→24、RX fragment 24→80（256B各片，共20KiB载荷池）。两条8KiB窗口外预留约4KiB载荷余量；还需包描述符、协议栈和系统并发验证，不能据此宣称永不丢包。服务公开TCP/HTTP队列仍为2KiB，最大连接数仍为2、HTTPS最多1，不增加无限缓存。

微雪构建：内部DRAM段184688B，IRAM74720B，修改网络池前后DRAM段不变；PSRAM静态段257568→274496B，增加16928B。该工程将这些网络池数据映射到PSRAM。TLS堆96KiB、内核动态堆96KiB、屏幕40MHz双8KiB内部中转保持原配置。音频会话另按需分配48KiBPSRAM和既有音频线程/解码器；不能把静态预留或WAMR上限误报成实际应用活跃使用量。

## 来源与验证原则

默认使用网易云站点的未登录HTTP端点获取三首示例元数据和当次公开播放地址；只接受code200、MP3、非试听限制且实际返回的URL，限定music.126.net CDN。不是承诺稳定的第三方开放API，不绕过付费/登录限制，不附带音乐素材，不意味着获得商用/再分发版权。可用状态取决于平台。本轮以开发板直连为准；PC使用VPN，PC能访问不等于开发板可访问。

微雪实机音频自检通过：131072B合法MP3前缀解码6456ms、89次部分写入、实际缓冲写满、暂停冻结/恢复、finish后拒写、正常EOF、空流及非法ID3失败、旧句柄拒绝。最后故意留空会话不关闭，再停止APP验证runtime回收，随后重新播放可申请会话。临时测试APP已卸载。原始日志和样本不入Git。

```bash
python tools/validation/audio_stream_check.py --sdk ../aster-sdk \
  --sample /path/to/sample.mp3 --output /tmp/aster-stream-check
```
