# Aster 可选音频能力与 FAKE POD S31 播放器设计

方案起点为 2026-11-15 的 `a66235e`。当前固件提供可选媒体服务，有线输出、手机蓝牙接收和 SBC 音箱输出均有实机记录。FAKE POD 从商城安装 Aster 音乐 0.4.27。下文的阶段日志保留当时的版本和测量值。

本地 MP3、WAV、FLAC 放在 SD 根目录的 `music/`；本地播放可拖动进度。手机蓝牙播放使用手机回报的曲目信息与时间，定位在手机端进行。播放器前台按曲库顺序续播，退出后固件继续播完当前曲目。系统下拉设置负责蓝牙连接。[播放器操作与歌词](https://github.com/hello-myj/aster-apps/tree/main/HiFiPlayer) · [USB 读卡器](power-adaptation.zh-CN.md#usb-读卡器)

## 1. 产品与验收边界

在 Aster 桌面和动态 AOT 应用体系内提供本地音乐播放器、有线耳机输出、经典蓝牙接收和经典蓝牙耳机输出。播放器返回桌面后可继续播放；系统统一管理音频焦点、音量、输出切换和错误恢复。BLE 遥控、LE Audio、USB UAC/MSC 不属于这一轮验收。

P4、lckfb 和模拟器不被要求实现 S31 的硬件能力。无对应实现时，统一接口返回明确的不支持结果，现有游戏和音频 ABI 保持兼容。

## 2. 方案启动时的硬件与软件基线

- ESP32-S31，双核，16 MiB PSRAM，16 MiB Flash，ESP-IDF 6.1 预览支持。
- CS43131 位于 I²C1 地址 0x30；I²S1 TX 为 BCLK52、WS51、DATA50，RESET53；板载 24.576 MHz 晶振，不连接 MCU MCLK。
- 厂商板级参考为有效 24-bit、32-bit 时隙，板级采样率上限 96 kHz。DAC 芯片的最高规格不能代替整机验收。
- PDM 麦克风使用 I²S0，CLK6、DATA2，与 DAC 分开。
- SD 为 4-bit SDMMC。音乐采用有限窗口顺序读取，不把整曲装入内存。
- 方案启动时通路以 PCM16 和 MP3 为主；32-bit I²S 时隙中填充 PCM16 不构成 24-bit 音频。
- 当时接口已含文件播放、暂停、恢复、音量、进度、歌词、MP3 输入流和短音效；缺少通用格式协商、输出设备、可持久后台媒体会话和蓝牙音频服务。
- CS43131 已通过身份和晶振就绪检查；耳机声音、采样率切换、24-bit 数据路径、录音和长期播放尚待实机验收。

## 3. 分层

### 3.1 公共音频层

位于 `common/audio/`，只依赖标准 C 和 Aster 内部类型。负责格式验证、可选输出操作表、焦点与会话规则、播放队列及状态机；不引入 IDF、Zephyr、I²S 或蓝牙厂商头文件。

### 3.2 系统服务层

IDF/Zephyr 提供线程、锁、存储和消息适配。解码、文件预读、PCM 消费由音频工作线程执行。WASM 回调、LVGL 绘制和蓝牙协议回调都不直接执行长时间 SD/I²S 操作。

蓝牙协议栈由 IDF 服务适配。接收到的数据进入有界队列，解码/输出在工作线程完成；回调中不写 SD、不驱动 DAC、不调用应用虚拟机。

### 3.3 板级层

BSP 只负责输出设备能力、时钟、DAC/I²S 配置、传输、静音/音量、电源与诊断。S31 提供 CS43131 实现；其他板可以完全不注册新输出后端。采用带 `size/version` 的 C 函数表，可继承默认行为并覆盖支持的操作。

### 3.4 应用与 SDK

播放器界面属于 `aster-apps`，通过 Aster 公共 ABI 操作媒体服务。音频数据不经 UI 的每帧回调搬运。SDK 通过契约快照提供公共头文件，APP 构建只读取所用 SDK；新增同架构、沿用现有 ABI 的板级音频后端时，应用仍使用现有接口。

## 4. 可选能力契约

分开查询：PCM 输出格式/采样率/声道、文件解码器、后台会话、A2DP Sink、A2DP Source、AVRCP。不能用一个“支持蓝牙”代替这些能力。

`caps` 表示实现的能力；运行状态另报未初始化、可用、未连接、正在播放、错误。蓝牙耳机未连接不等于芯片不支持 A2DP。

- 缺少可选操作：`ENOTSUP`；硬件未初始化：`ENODEV`；格式不支持：`ENOTSUP`；参数非法：`EINVAL`；设备被其他会话占用：`EBUSY`。
- 不使用成功占位函数，不伪造播放成功、音频输入可用或已连接。
- 通用输出支持查询、打开、写入、排空、停止、关闭和统计；成功打开后必须具有完整生命周期操作。
- 帧数表示一组完整声道采样，不能混同字节数或单声道样本数。
- 明确区分有效位深、内存容器、字节序、声道数与 I²S 时隙。
- 接口保留 `size/version` 与保留字段；发布前通过 ABI 兼容检查。
- 新导入需要对应最低 ABI 版本。能力查询不能绕过旧固件的导入解析；旧 4.3 应用继续使用原来的接口。
- 固件在启动 APP 前检查必需能力。将蓝牙声明为可选能力的播放器也能在仅支持有线音频的设备上运行。

## 5. 音频数据路径

本地有线播放：SD 卡文件 → WAV、FLAC 或 MP3 解码器 → PCM → I²S/CS43131 → 有线耳机。

已验证的蓝牙接收路径：手机 → A2DP Sink → SBC 解码 → PCM → CS43131 → 有线耳机。

已验证的蓝牙发送路径：SD 卡文件 → 解码与采样率转换 → SBC 编码 → A2DP Source → 音箱。AAC 互操作性仍待验证。

有线高保真独占模式保留源位深和采样率；仅在明确请求且硬件不支持原格式时转换，并向界面报告实际输出格式。低采样率游戏/提示音继续走兼容路径。EQ、ReplayGain、音效混合等会改变 PCM，必须可关闭，不能在启用时标为 bit-perfect。

## 6. 格式与时钟

第一阶段验证 PCM16 44.1/48 kHz 左右声道，再验证 24-bit WAV 和 88.2/96 kHz。随后加入 FLAC 原位深解码。MP3 保留当前原采样率输出能力。

PCM 内存格式候选为 S16LE、S24LE（3 字节）和 S32LE；24-bit 源样本转换到 32-bit I²S 时必须保留全部有效位，不先缩到 16 位。

44.1/48 kHz 系列分别核对 DAC 时钟域和 ESP I²S 的实际配置。板载 24.576 MHz 晶振并不自动证明任意采样率都准确。切换时先静音、排空/停止 DMA、重配时钟与格式、预填充后恢复；任一步失败必须释放资源并报告错误。

DAC 音量与软件增益分开处理，默认不使用正数字增益。低音量验证开始/停止、切歌、插拔及采样率切换时的爆音。耳机插拔/阻抗检测仅在原理图连接和实测支持时作为可选能力开放。

## 7. 后台播放与焦点

媒体服务持有当前曲目的解码器和输出端点。现有播放器 APP 维护前台播放列表并发起下一曲，退出 APP 后媒体服务可以播完当前曲目。后台播放必须显式建立系统媒体会话，普通游戏退出仍清理其声音资源。

状态：IDLE → OPENING → BUFFERING → PLAYING ↔ PAUSED → DRAINING → ENDED；任一步可进入 ERROR，停止请求优先于下一首和重试。

首版保证一个媒体源拥有输出。音乐、游戏、提示音与蓝牙接收使用明确的焦点策略；独占高保真模式下提示音延后或禁用。禁止两个线程分别重配同一 I²S/DAC。

原设计还规划了独立的系统队列，包括增删曲目、单曲或列表循环、随机播放和断点续播。完整的后台队列仍待实现与验收。曲库扫描可取消、分批运行，缓存歌曲信息；专辑封面采用尺寸和内存上限。持久状态不写入音频回调。

## 8. 蓝牙服务

Sink 与 Source 分开声明和启用；首版按模式切换，不同时运行。SBC 先验收，AAC 在官方外部 codec 路径可用后加入。其他编码器不预先宣称支持。

提供设备发现、可发现性、配对确认、已配对设备、连接/断开、手动重连、有限退避重连、连接状态事件和编码协商状态。

AVRCP 对接播放/暂停、上下首、曲名/作者/专辑、播放状态及音量同步；处理远端音量与本机音量的回环。蓝牙 SBC/AAC 是有损链路，界面显示实际协商编码，不标作无损直通。

Wi-Fi 下载与蓝牙播放需共存实测。临时缺包通过缓存和有界恢复处理，不让 UI 卡死；断连释放缓存与 DAC 焦点。

## 9. 内存、调度与诊断

音乐缓存按会话申请，优先使用 PSRAM；DMA、协议栈以及必须内部存储的任务资源使用 SRAM。停止/失败后释放缓存，不常驻整曲数据。各任务的优先级和核绑定以实测为准。

提供当前源/输出格式、有效位深、播放帧数、排队帧数、缓存水位、欠载、I²S 错误、解码错误、蓝牙丢包/重连、内部堆余量和最低余量。

设置独立 CLI 诊断，不依赖播放器界面。测试音有时长和音量限制，初次测试确认耳机已连接，以低音量验证左右声道。物理听感、数字数据路径验证、模拟音质指标分开记录。

## 11. 验收样本

- 44.1/48 kHz PCM16：左声道、右声道、双声道、静音，时长和音调正确。
- PCM24：含最低有效位的测试样本保持到 I²S 32-bit 容器；无截断/符号溢出/左右交换。
- 88.2/96 kHz：数字格式、连续输出和时钟切换；音质指标只有外部测量后才记录。
- WAV/FLAC/MP3：短曲、长曲、空文件、截断文件、不支持格式、单/双声道，暂停/恢复/seek/自然结束。
- 后台：退出 UI、打开其他 APP、反复切歌、SD I/O 失败，停止后解码器/缓存/输出资源回收。
- 蓝牙：手机接收、耳机发送、远端控制、断连重连、协商失败、Wi-Fi 并发。
- 可选适配：无后端与部分后端返回准确错误；没有支持的板不会新增常驻音频/蓝牙任务。
- 既有游戏：音效、音乐、录音和应用退出清理回归。


## 12. 实施记录

### 2026-11-15：公共输出与 S31 原位深 PCM

- 新增 `common/audio/aster_audio_output.*`：可选注册、继承/方法覆盖、格式协商、分块写入、排空、关闭和状态查询。内部错误采用负 errno，尚未加入 WASM 公共 ABI。
- 16/24/32 位小端 PCM 转为 I²S 的 32 位容器。主机测试验证正负极值、24 位最低有效位、32 位低位，以及无后端、不支持格式、部分写入和关闭失败等情况。
- S31 新输出使用 CS43131，独占 DAC；旧游戏音频的写入、重配置、关闭和录音操作不能拆除正在使用的原位深输出。分块转换缓冲 4096 字节，打开时从 PSRAM 申请，关闭/失败后释放；没有申请整曲缓存。
- 新增仅 S31 的 `aster-audio status` 与 `aster-audio tone RATE 16|24|32`。测试音在后台任务运行，左/右各 2 秒，低电平、边缘包络，结束恢复音量。
- 主机测试通过；S31 和 P4 IDF 构建通过。P4 本轮只做构建回归，没有重刷。
- 初次 48 kHz / PCM24：192000 帧、驱动错误 0，用户确认左右声道正常、无杂音。44.1 kHz / PCM16：176400 帧、驱动错误 0。
- 初测 88.2/96 kHz 被默认 XTAL 时钟配置拒绝；S31 TX 切换音频 APLL，后续以重测日志为准。CS43131 维持板载 24.576 MHz 晶振，未使用 MCU MCLK 引脚。
- M2 仍待 APLL 各速率重测、清理恢复与原应用音频回归；未将后台音乐、FLAC、播放器或蓝牙标记完成。欠载计数尚未接入硬件事件，不能用其初始值代表无欠载。


APLL 重测结果：

- 44.1 kHz / PCM16：176400 帧，4005 ms，驱动错误 0。
- 48 kHz / PCM24：192000 帧，4001 ms，驱动错误 0。
- 88.2 kHz / PCM24：352800 帧，4002 ms，驱动错误 0。
- 96 kHz / PCM32 容器：384000 帧，4001 ms，驱动错误 0。

先前实时 `sin(double)` 生成测试音在高采样率下供数不足；改为整数相位查表并使用短包络后，四组均达到预期时长。以上是发送帧数与用时验证，不代替外部时钟精度、模拟信噪比或欠载硬件计数。APLL 版本实听及旧应用回归单独确认。

实听补测：按用户要求分别重播 44.1/48 kHz 和 88.2/96 kHz，统一使用 PCM24、每组左/右各 2 秒。88.2/96 kHz 重播后用户确认“没问题了”。各档测试音的实听确认不代表完整音乐播放器、蓝牙链路或模拟音质指标已验收。


### 文件播放与新卡开机验证

- `common/audio/aster_audio_decoder.*` 使用固定版本 dr_libs 的 WAV/FLAC 解码，文件/分配通过 `aster_os`，不依赖 IDF。选择 MIT-0 授权，保留上游完整头文件与固定提交/摘要说明。
- WAV PCM16/24/32、原生 FLAC16/24/32 输出左对齐 s32；不经 s16 中间格式。源采样率仅接受当前输出契约支持的 32/44.1/48/88.2/96 kHz；不支持的编码/采样率明确报错，不自动降位深。单声道在输出前复制到左右声道。
- 解码器动态分配预算 768 KiB；另有固定对象/转换区。常见 FLAC 样本解码器动态分配峰值 41272 字节。PCM、DAC 转换和任务栈按会话申请，停止/结束回收；不是整曲解码。
- `common/audio/aster_media.*` 为系统所有的后台会话，控制命令不做文件 I/O。当前支持单文件播放、暂停、继续、毫秒跳转、停止、状态/进度和错误结果；暂未实现播放队列、独立读前缓存、MP3 新通路或 APP 公开 ABI。
- 新卡首次开机：设备确认 sd=1；用户完成网页配网；SETUP phase=9、error=0、96404076/96404076 字节；应用列表确认商城 0.3.1。
- 两张卡的串口上传都发生过 ACK 超时。IDF 6.1 stdio 默认 USB RX 为 256 字节，小于 ASTERFS 的 512 字节数据帧；S31 板级链接包装将安装时 RX 下限设为 2048，其他板不变，不修改外部 IDF 目录。修改后上传 FLAC 513724 字节与 WAV 576044 字节，10.5 秒完成，两文件 CRC 校验通过。
- 实机 FLAC48k/24bit/双声道：完整播放 576000 帧/12 秒，error=0，用户确认连续正常、无杂音；前后 PSRAM 空闲均 14737824 字节。PCM24 WAV：完整播放 96000 帧/2 秒、error=0。
- 播放时启动商城 AOT、退出商城：媒体保持 PLAYING，帧数从 122880 继续到 152064。暂停后的两次快照均停在 167424 帧，确认不会继续推进。
