# N3 MQTT/MQTTS 公共接口与 APP 验证（已完成）

本记录延续 [双板 CLI 门槛](network-n3-cli-2026-10-16.md)。公共契约、SDK、模拟器与临时 APP 在各仓库 main 工作区实施和验证，本记录随N3代码本地提交；未推送或发布。CLI 阶段使用 ABI3.10；本阶段使用 ABI3.11.0，不能将两个阶段的镜像哈希或资源字节数混用。

## 契约与执行模型

- 公共头文件 `contract/include/aster/mqtt.h`；通过固件导出/SDK导入工具同步，不手写导入清单。新增9个 `aster_mqtt_*` 导入和能力位19（`mqtt`）；权限仍为`net`，MQTTS另需`tls`。APP不能管理Wi-Fi或跳过证书验证。
- connect输入80B、status输出64B、整消息输出1176B，固定宽度、显式长度、size/version；消息topic不保证NUL结尾。native桥接先验证/复制输入、先验证输出再消费消息，允许非对齐缓冲，不跨调用保留guest指针。
- 所有公开错误映射到稳定ASTER域；operation返回OK后仍须检查输出error。QoS1收到PUBACK不等于业务执行完成；保留最近4个完成结果，没有离线无限队列或业务消息自动重发。
- MQTT与TCP/UDP/HTTP共用两个连接，MQTTS/HTTPS共用一个TLS名额；4个过滤器、2条接收消息、2个操作、主题128B、消息1024B。重连恢复已确认订阅；接收队列不排空可能因背压导致心跳超时。
- 没有新增MQTT专用线程。共享HTTP 8KiB与网络4KiB worker，服务关闭后私有缓存释放，已初始化worker栈仍保留。
- 本次为增量ABI3.11；既有网络导入将在规划中的N6统一迁移并移除，N3没有提前引入统一分派器或旧网络兼容层。

- 固件111项、SDK105项主机测试通过。固件全量初次运行发现旧音频测试夹具缺少原生采样率状态、运行时清理测试缺少流式音频回收mock；已更新夹具，复测通过，没有更改音频运行逻辑。
