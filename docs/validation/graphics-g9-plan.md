# G9 复合回归与配套发布准备

状态：已准备，尚未开始G9实机测试，未发布。G8两板基础质量验收见 [G8记录](graphics-g8-2026-10-14.md)。本文件随固件源码维护；原始日志、截图、镜像和临时APP放源码仓库外。

## 2. 优先定位微雪冷绘制延迟

G8同一质量页：旧字库冷约708–710ms；12px C字库三轮953ms，首次重启976ms；热绘制约65.6ms。此为整页编码/绘制/提交，不能称单字耗时或光学FPS。设备不运行FreeType；目前未分离字库数据与SD文件布局影响。

1. 使用同一板、镜像、APP、页面与SD卡，保留新旧字库及manifest备份；记录文件哈希和大小。
2. 先在不改变实现的情况下复测C字库；每组至少三轮，独立记录应用会话首帧和后续12热帧。应用重开不等于断电或所有存储缓存清空。
3. 在独立临时路径准备旧、新字库，分别用相同替换流程切入正式路径，重启后验证实际加载的字体。交替测量A/B/A，避免把先后顺序和文件重写差异直接归因于字形算法。
4. 记录 `aster sys fonts` 前后差值：命中、缺失、读取次数/字节、加载总耗时与最长耗时、预热耗时；32位累计计数需处理回绕。保留页面总时间，不能用累计加载时间替代它。
5. 若现有统计不足，再增加有界诊断，区分索引查找、文件定位/读取、字形解码及页面预热；诊断构建与日常构建分开，不逐字刷串口。
6. 根据证据选择读取合并、预热去重或有界缓存调整；每项单独对照。不直接增大DRAM或恢复PSRAM直DMA，不以损失C字库清晰度换取未经评估的速度。

通过条件：原因有可复现实验证据；修复后同场景冷/热数据和内存代价明确，字体度量与外观通过。若仍未解决，明确保留问题，不将G9全部标完成。

## 3. 主机与两板复合回归

依次执行固件/SDK单元测试、文档和字体度量检查、模拟器契约检查与真实APP集成。发布验收要求必需样例全部存在、零跳过；G8模拟器7项外部包缺失跳过不能当作发布通过。

每块板分别覆盖：全帧clear与矩形；中文冷/热缓存和局部HUD；不透明/半透明图片及1:1/缩放；远离脏区；sprite移动/隐藏/删除；Scene静止无重复发布；小ring/arena及中途错误；普通surface与panel canvas。

继续检查launcher滚动、上下拉、返回确认/取消、截图、暂停/恢复和反复切换APP。记录错误码分布、完整帧/传输字节、内存起止与峰值，正常EBUSY单独分类。只能在有完整帧完成计数时计算完成帧率；无光学测量则明确说明。

并发范围为图形、触摸、音频调用和板型支持的IMU；微雪禁用IMU不算通过IMU并发。时长执行前固定，不自动扩大为30分钟；手动操作和断线均记时间，意外断电的轮次不能算连续完成。无需额外要求音频实听。

## 4. 物理I/O故障恢复（仍待验证）

先审查总线/驱动超时、错误传播、DMA所有权、锁释放及下一帧恢复，再设计可控故障。软件注入仅证明软件错误路径，不代替物理故障。

真实断电、接线或存储介质操作必须先准备可审查步骤并通知用户；保存数据，在静止且确认无文件写入时操作。供电中拔SD可能损坏文件系统，不能作为默认测试。没有可安全执行的物理方案时明确保留待测。

验证失败不能虚报present成功、继续复用在途DMA缓冲或丢失恢复所需脏区；恢复后画面完整、触摸可用、APP可退出，内存/句柄不持续增长。设备完全掉电后的文件/版本恢复和运行中显示总线错误分别记录，不混为一种恢复能力。

## 5. 配套版本与收尾

复合回归稳定后，审查 `contract/release-matrix.json` 的SDK/模拟器固定提交、工具链哈希和必需包。现有矩阵是此前发布基线，不能直接声称它已覆盖G8。更新候选矩阵后运行 `tools/release_check.py`，按其要求使用干净工作区和全新输出目录；失败/跳过项必须处理后再称发布通过。

核对同一SDK下载包内开发工具、两板固件、系统资源与Windows模拟器的版本关系和哈希；APP SDK构建不引入固件开发环境依赖。准备产物和发布说明不代表已获准推送、建tag或发布Release；这些外部动作另按用户指令执行。

最后卸载临时APP、清理SD源包、核对原APP集合/存档，恢复原音量和日常前台应用。精简结论写入源码侧G9验收记录，包括实测数据、限制与未测项；原始诊断材料留本地。全部约定验收范围通过后，才将G9标题标记“（已完成）”。
