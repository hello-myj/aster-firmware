# APP 安装、升级与启动

每个应用使用两个程序槽和各自的提交记录。用户数据留在稳定目录。公开包格式不变。

## 设备目录

```text
/SD:/aster/apps/<id>/
  .active0                 槽 0 提交记录（24 字节）
  .active1                 槽 1 提交记录（24 字节）
  .v0/                     程序槽 0：package.ast、app.wasm、app.aot、manifest.json，可选 icon.bin 与 assets/
  .v1/                     程序槽 1，布局相同
  data/                    用户存档
  cache/                   用户缓存
```

旧的平铺布局仍可启动。第一次升级写入空闲槽，不移动已有存档。卡上需要能同时放下当前版本和一个完整新版本。

## 安装顺序

1. 检查包、ABI、CPU/AOT、签名和 APP ID。主版本不是 4 的包返回 ABI 不兼容。
2. 有应用正在运行、暂停或启动时返回忙。先回到桌面再安装。
3. 校验两份提交记录，选择非当前槽。读不到确定状态时拒绝修改。
4. 删除备用槽的旧提交记录，清槽并写下 `.installing`。当前槽保持不变。
5. 写入包、WASM、AOT、图标、资源和 manifest，并读回核对。
6. 保留已有 `data/` 和 `cache/`，去掉 `.installing`。
7. 写入该槽的提交记录并读回。
8. 刷新注册表。启动使用刷新后的那一代程序和资源。

## 启动时的选择

提交记录包含 `ASTV`、格式版本、序号、槽号、manifest CRC 和记录 CRC。扫描时跳过长度不对、CRC 失败、未完成或缺少程序文件的槽，在完整候选里选序号最新的槽。两个槽都不可用时，再尝试旧的平铺布局。

`/assets` 来自选中的槽。`/data` 和 `/cache` 始终在应用根目录。
