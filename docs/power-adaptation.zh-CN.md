# 电源与实体按键适配

系统内部接口位于 `common/port/aster_power.h`，不改变 APP 的 WASM/AOT ABI。
公共实现不依赖 ESP-IDF、Zephyr、PMIC 型号或 GPIO 编号。

## 硬件操作表

`aster_power_ops_t` 提供能力查询、电池读取、屏幕开关、CPU 休眠、重启、关机、实体按键读取和语义映射。
`aster_power_device_base` 使用既有设备接口提供屏幕与按键的默认实现。

新板调用 `aster_power_derive(&board_ops, &aster_power_device_base, &overrides)`：
非空回调覆盖父表，其余方法继承；如需删除继承的方法，派生后显式置空。
操作表、名称和 context 必须具有静态生命周期，所有继承方法接收同一个 context，不能隐含使用另一张父表的 context。
`aster_power_bind()` 在启动阶段注册，`aster_power_seal()` 后不能替换，避免运行中的表和驱动被换掉。
OS 生命周期表同样支持 `aster_power_lifecycle_derive()` 局部覆盖。

能力声明区分熄屏、浅休眠、深休眠、重启和关机，三个可唤醒模式分别声明唤醒源。
例如触摸可以唤醒仅关闭背光的设备，并不表示该触摸 GPIO 能从深休眠中唤醒 CPU。
不支持的方法为 NULL，查询/执行返回负 errno。能力查询会过滤没有回调的方法。
电池数据通过有效标志区分无电池、未知电量、有效百分比和有效电压，不从电压假算百分比。
硬件原始按键 code 不进入 Launcher 的板型判断；板级 map_key 回调映射为系统语义。

## 系统生命周期

`aster_power_lifecycle_t.prepare/finish` 是 OS/应用/文件系统收尾适配。
CPU 休眠、重启、关机必须同时具备硬件方法和这两个钩子，否则能力查询过滤该功能。
prepare 成功前必须获得排他状态，停止新安装/下载，结束或暂停 VM 与音频，等待工作线程完全退出，完成存储同步。
失败时 prepare 自己恢复未完成的准备；成功后，硬件调用返回时公共层总会调用 finish，负责唤醒或失败恢复。
熄屏只改变显示，不停止后台蓝牙或本地音乐，不执行破坏性收尾。

所有运行期接口由系统 UI/VM 的同一个 owner 调用；总线竞争由驱动内部处理。
绑定表不可变不代表驱动自动线程安全。其他线程需要通过命令队列交给 owner，不能直接调用此状态机。

## 公共熄屏策略

`aster_power_idle_t` 提供无分配、无常驻任务的超时状态机。
timeout=0 表示从不自动熄屏，inhibited 用于按住触摸、安装等临界阶段。
用户活动刷新计时；熄屏后的首次触摸会唤醒并吞掉该次手势，直到全部触点抬起，避免唤醒时误点击。
Launcher 和应用覆盖层共用策略，设置独立保存，不改变旧设置的存储格式。

## 当前接入范围

- 三块板共用可滚动设置、自动熄屏、立即熄屏与触摸唤醒。
- S31 状态栏用 LVGL 几何图形绘制电池外框、百分比填充和充电闪电，不依赖字库图标；低电量使用警示色。
- S31 额外读取 AXP2101 电池状态/充电状态/百分比。上方 AXP2101 电源键短按熄屏或唤醒，持续按住约 3 秒出现关机界面，无需先松手；关机后用同一键开机。下方 GPIO61 是另一颗实体键。
- 蓝牙入口按已注册播放器服务能力显示；没有对应能力的板不显示蓝牙入口。
- 鱼鹰光电 P4C5 和立创 ESP32-S3 实战派接入重启；FAKE POD NANO PRO 接入重启、AXP2101 软件关机。GPIO/定时浅休眠仅作为实验选项，默认关闭；普通熄屏时后台音频可继续。无相应后端的功能仍不显示。深休眠没有验证可用的物理唤醒路径，未启用。
- P4/lckfb 未确认电池检测硬件，不显示虚构的电量。

### 滚动设置中的滑条手势

亮度、音量保留扩大的触摸区域。在 LVGL 滑条类处理之前先判断手势方向：尚未超过手势阈值时不修改数值；纵向手势交给设置页滚动，整次手势都不修改或保存亮度/音量；横向手势继续调节，短点轨道仍可选择数值。
`tests/test_slider_axis.py` 验证方向锁定、快速滑动、点击与输入设备兼容；模拟器 `desktop/test_mixer_gestures.py` 经真实 LVGL 触摸链路验证两根滑条上的纵向滚动不改配置、横向拖动仍能调节。


熄屏设置与立即熄屏使用加高的独立按钮，紧凑屏幕上也保留至少 56 物理像素高度、18 物理像素间隔。按钮保持整次触摸归属，超过拖动阈值或丢失按压时取消点击；即使位于滚动边界，也不把滚动释放当作立即熄屏。


公共设置页会逐个消费触摸采样，保留真实按下位置，避免多个采样在一次 LVGL 读取前覆盖。横向意图需要明显的水平位移和连续不同坐标的确认；静止坐标的重复读取不算确认，移动后仍不明确的释放按取消处理。这些规则在共享 Launcher 源码中实现，ESP-IDF、Zephyr 和桌面均使用同一份逻辑，无按芯片分支或单板阈值。

## 电源生命周期实现

内部电源适配接口版本为 3，保留恢复结果反馈，增加可选 USB 存储会话；APP ABI 仍为 4.5。
`aster_power_schedule()` 是线程安全的单请求邮箱；APP/UI owner 通过 `aster_power_poll()` 在 VM 完整清理后执行。请求期间禁止新 APP 启动和应用交接。
公共 `aster_power_session` 负责关闭任务入口、停止音频、等待在途任务、关闭网络、卸载 SD，以及浅休眠醒来或失败后的恢复。
安装、串口传输、首次开机工作线程、Wi-Fi 操作及原生音频会话持有活动租约，新任务在收尾期间返回忙。已有关键事务可以完成；等待超时会取消电源操作，恢复任务入口，不卸载仍在使用的存储。
浅休眠时若媒体或蓝牙会话正在使用，则拒绝请求并保留播放。重启/关机则等待媒体、蓝牙和旧音频服务退出。

电源状态页位于 `common/ui/`，使用既有固件系统字体，不依赖 SD 字库；关闭字体文件、排空显示传输后才卸载 SD。恢复失败通过生命周期的 `recovery_error` 返回并显示错误。

### 适配范围

- ESP-IDF 和 Zephyr 均复用公共邮箱、任务门控、准备/恢复流程及 UI，仅提供各自调度、音频、网络和存储方法。
- 鱼鹰光电 P4C5：重启，触摸熄屏唤醒；未宣称已适配 MIPI 显示恢复后的 CPU 休眠。
- 立创 ESP32-S3 实战派：重启，触摸熄屏唤醒；未声明软件切断电源或 CPU 休眠。
- FAKE POD NANO PRO：浅休眠后端已接入触摸 IRQ GPIO45、底部按键 GPIO61 和定时器，实机恢复尚未通过。默认关闭 ASTER_FAKEPOD_EXPERIMENTAL_LIGHT_SLEEP，不发布浅休眠能力或显示对应按钮，CLI 同样拒绝休眠；既有熄屏不受影响。软件关机只写 AXP2101 的软件关机位，不改变稳压/充电参数；关机后由上方 PMIC 电源键重新开机。
- ESP32-S31 的 RTC GPIO 只有 0..7；本板触摸/按键不在其中，因此不把浅休眠唤醒能力误报为深休眠支持。

### CLI

`aster power status` 查看请求状态和活动租约；`aster power restart` 请求重启；支持的板可用 `aster power off` 或 `aster power sleep`。
ESP-IDF 额外提供 `aster power sleep 5`，仅以定时器在 5 秒后唤醒，供恢复路径诊断。

### USB 读卡器

FAKE POD NANO PRO 的构建选项 `CONFIG_ASTER_FAKEPOD_USB_STORAGE` 默认关闭。可用 menuconfig 开启 “Enable USB SD card reader”，或在新构建配置中将 `sdkconfig.defaults.usb-storage` 叠加到板卡的 `sdkconfig.defaults`。

鱼鹰光电 P4C5（ST7102）的 `CONFIG_ASTER_OSPTEK_USB_STORAGE` 默认开启，可以在 menuconfig 关闭。用数据线将电脑接到原生 USB Type-C，CH343 下载口可同时保留。FAKE POD 使用同一个 Type-C，若只识别到串口，翻转设备端插头即可。

启用后，桌面下拉设置出现“USB 读卡器”，ESP-IDF 也可用 `aster power usb`。SD 卡以 USB 大容量存储设备出现，可把 MP3、WAV 或 FLAC 文件放入根目录的 `music` 文件夹。

连接前，系统退出当前应用、停止音频、等待读写任务结束并卸载 SD。USB 会话内由电脑独占 SD，设备显示操作提示。电脑安全弹出后会话自动结束，可拔线。若操作系统只停用设备、没有发送弹出命令，安全弹出后拔线也会结束会话。回到桌面后可重新打开曲库。

其他板可在各自的电源适配器声明 `ASTER_POWER_USB_STORAGE`，并提供 `usb_storage` 回调。回调运行期间 SD 已由系统卸载，返回时要确保 USB I/O 已结束、USB 已释放，系统再挂载 SD。仅有 USB 串口的设备不声明此能力。
