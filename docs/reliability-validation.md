## 剩余硬件验收

### 存储容量与真实介质故障

- [ ] 使用独立测试 SD 卡验证真实满盘：分别在程序槽写入、资源写入和提交记录写入时耗尽空间。
- [ ] 验证非注入的介质写入、短写或同步故障；记录实际底层错误、复现方法及 SD 型号，不把软件注入结果当作此项通过。

通过标准：不报告 installed OK；错误包含阶段/操作；已有完整版本和用户数据保留，释放空间或更换正常介质后可安全重试。故障测试应先备份卡内容，使用 test.p0.* APP，不占满或破坏用户原卡。

### 更多断电时刻与介质覆盖

- [ ] 在写入备用槽、清理旧提交记录、移除 .installing、写入提交记录及同步过程中断电，增加重复次数；当前两个已通过点均在文件关闭后。
- [ ] 使用不同型号 SD 卡重复关键掉电用例，记录型号、容量、文件系统及次数。

通过标准：启动只选择完整旧/新版本，不混用程序和资源；用户 data/cache 字节保留；重试成功。commit 同步/关闭失败可能已完整落盘，允许选择完整新版本，不能断言失败响应一定意味着版本没变。物理写入过程中拔电仍可能损坏介质，有限检查点不能证明所有 FAT/SD 掉电语义。

### 长期资源与空间稳定性

- [ ] 长期循环安装失败、升级、重试、启动失败、Trap、正常退出和超时恢复，测量 SD 空间、内部堆、PSRAM 最大空闲块、文件/句柄、字体、音频和异步任务资源。
- [ ] 增补会正常返回但超过期限的有限长回调实机用例，以及合法同步 Host 操作接近期限的用例。

通过标准：预热后没有随循环次数持续增长的占用；两个版本槽和兼容平铺版本之外不积累无界文件；停止后服务可用，回调超时行为符合策略。已测短循环的内部堆前后相同，但 PSRAM 最大空闲块估计存在变化，不能据此宣称所有资源完全回到基线。

## 保证边界

回调保护线程依赖可调度抢占，不能保证中断关闭、内核/驱动损坏或硬件失锁后的恢复。完整芯片复位中断其他服务，不保证尚未关闭/同步的写入保留。此方案不提供不可信 APP 的强制隔离保证；独立硬件 watchdog 和 AOT 安全边界需要另行验证。
